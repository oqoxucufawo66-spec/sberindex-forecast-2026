**Прогноз потребления в муниципалитетах и раннее обнаружение шоков на данных СберИндекса**

## Задача

По условиям конкурса нужно построить алгоритм, который:

1. **прогнозирует потребление в муниципальных образованиях (МО)** и по качеству
   (MAE обязательно, R² дополнительно) превосходит базовую модель организаторов — **Prophet**;
2. **как можно раньше и точнее выявляет точки структурных изменений** (шоки) в рядах.

Модели сравниваются на горизонтах **1, 3, 6 и 12 месяцев**.

Мой акцент — **интерпретируемость**: не только «насколько вырастут или упадут расходы»,
но и *почему* модель так считает и *что именно* изменилось в структуре потребления территории.
Для этого разбираю прогнозы через SHAP и привязываю найденные шоки к реальным событиям.

## Данные

Используются только открытые и проверяемые источники.

| Источник | Что берём | Роль |

| [СберИндекс: индекс покупательской мобильности](https://sberindex.ru/ru/dashboards/indeks-mobilnosti) | мобильность покупателей | дополнительные признаки |
| [Росстат: база показателей муниципальных образований](https://rosstat.gov.ru/storage/mediabank/Munst.htm) | население, зарплаты | нормировка и статические признаки МО |

## Подход

```
 данные СберИндекса ──► очистка и склейка МО ──► признаки ──┬─► прогноз (1/3/6/12 мес.) ──► MAE, R²
 Росстат, календарь ─┘                                     │
 новости (МО × месяц) ────────────────────────────────────┘─► шоки: офлайн-разметка + онлайн-тревоги
                                                                    │
                                              SHAP, карты, разбор реальных примеров ◄┘
```

### 1. Прогнозирование

| Модель | Тип | Зачем |
|---|---|---|
| Наивная, сезонно-наивная | базовые | нижняя планка: «как в прошлом месяце» / «как год назад» |
| **Prophet** | базовая модель организаторов | ориентир, который нужно превзойти |
| **LightGBM** (глобальная, прямая стратегия) | градиентный бустинг | одна модель на все МО и категории, отдельная на каждый горизонт; признаки — лаги, скользящие средние и разброс, годовой и месячный прирост, сезонность, категория; при необходимости сравню с CatBoost |
| **Chronos-Bolt** (и при возможности TimesFM) | фундаментальные модели временных рядов | zero-shot прогноз без обучения на наших данных; сравнение с бустингом и ансамбль |

- Целевая переменная — `log1p(расходы)`, чтобы МО разного масштаба были сопоставимы.
- Признаки строятся **только из прошлого** относительно точки прогноза.
- Валидация — **rolling origin** (скользящая точка отсчёта): обучение до месяца *t*,
  прогноз на *t+h*, несколько срезов подряд. Случайного перемешивания нет.

### 2. Обнаружение точек структурных изменений

| Метод | Режим | Роль |
|---|---|---|
| PELT, Binary Segmentation (`ruptures`) | офлайн, по всему ряду | ретроспективная разметка исторических шоков |
| CUSUM по остаткам прогноза | онлайн | **раннее** обнаружение: тревога, когда факт систематически уходит от прогноза |
| Bayesian Online Changepoint Detection | онлайн | вероятностная оценка смены режима (в планах) |

Сравнение методов — по precision / recall / F1 с допуском ±2 месяца и по
**средней задержке обнаружения** (сколько месяцев проходит от шока до тревоги).

### 3. Новости

Новость привязывается к МО по упоминаемым топонимам (справочник МО СберИндекса),
к месяцу — по дате публикации. В признаки для прогноза с точкой отсчёта *t*
попадают только новости, вышедшие не позже *t*. Польза новостей проверяется
абляцией: метрики с новостными признаками и без них.

### 4. Интерпретация и визуализация

- SHAP: какие факторы (инерция, сезонность, недавний сдвиг, новости) двигают прогноз конкретного МО;
- карты МО: ошибка прогноза, найденные шоки, изменение структуры трат по категориям;
- разбор нескольких реальных муниципалитетов: что произошло, когда модель это заметила, чем объясняется.

## Метрики

- **MAE** — основная метрика (обязательная по условиям конкурса), по каждому горизонту 1/3/6/12;
- **R²** — дополнительная;
- WAPE — для сравнения МО разного масштаба;
- для шоков — precision, recall, F1, средняя задержка обнаружения.

Результаты на реальных данных появятся здесь после бэктеста.

│   ├── pipeline.py               # сквозной бэктест
│   └── models/

│       ├── gbm.py                # LightGBM по горизонтам + SHAP

## Как запустить

```bash
git clone https://github.com/oqoxucufawo66-spec/sberindex-forecast-2026.git
cd sberindex-forecast-2026
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# опционально, для фундаментальных моделей:
pip install -r requirements-fm.txt

# 1. Скачать данные в data/raw/ (см. data/README.md)
# 2. Проверить сопоставление колонок в configs/default.yaml -> data.columns

python scripts/eda.py                      # сводка и графики в reports/eda/
python scripts/run_backtest.py             # наивная, сезонно-наивная, LightGBM
python scripts/run_backtest.py --models naive seasonal_naive prophet lightgbm

pytest -q                                  # тесты
```

Результаты бэктеста сохраняются в `reports/runs/<дата_время>/`
(`predictions.csv`, `metrics.csv`).
